# goszakup-bot — заключение и ТЗ

Документ по итогам отладки полного цикла подачи заявки на `v3bl.goszakup.gov.kz`.
Кратко: что работает, чему научились о сервере, каким бот должен быть в идеале и
как с сервером работать дальше.

---

## 1. Заключение (коротко)

Бот **проходит весь цикл автоматически**: логин по ЭЦП → создание заявки → лоты →
генерация и подпись всех документов → `docs_next` → шифрование цены через TumarCSP →
подпись → финальная подача (`ajax_public_application`). Полный прогон ~40 секунд от T0.

**Все программные блокеры устранены.** Оставшиеся препятствия — **внешние, не код**:
1. Лицензия и API-ключ TumarCSP (истекают — надо продлевать у ГАММА Технологии).
2. Баланс электронного кошелька для обеспечения заявки (1% от плановой суммы).

## 2. Что было исправлено (уроки сессии)

| Симптом | Реальная причина | Фикс |
|---|---|---|
| 403 «Доступ к документу запрещён» на скачивании | download-URL требует **два** сегмента: `/files/download_file/{file_id}/{access_token}/`, а бот слал один | `extract_download_targets` берёт оба сегмента |
| Зависание опроса перед T0 (долбёж 2/сек) | `_classify_create_poll` не знал стадию `priceoffers`; черновик, ушедший вперёд, не распознавался | добавлена стадия `priceoffers` в распознавание существующего черновика |
| `could not resolve app_lot` при повторном запуске | черновик уже на стадии priceoffers, маппинг лотов не на тех страницах | `AlreadyAtPriceStage` → пропуск фазы документов, resume сразу к цене |
| `SetAPIKey`/CryptoSocket не стартует | истекли **лицензия CryptoSocket** и **EFC API-ключ** (обе даты 01.07.2026) | продлить у вендора; ключ авто-снимается из лога CryptoSocket |
| Двойной инстанс → Telegram Conflict + конкурирующие логины | падавший прогон не завершал процесс; копились зомби | требование: **строго один инстанс** |

> Важно: 403 **не был** связан с сессиями/параллелизмом/Referer — только с URL.
> Много времени ушло на ложные гипотезы; вывод — сначала снять ground truth
> (реальный ответ/разметку сервера), потом чинить.

## 3. Как устроен сервер goszakup (протокол — самое ценное)

Эти факты неочевидны и добыты реверсом; на них держится вся логика бота.

1. **Одна активная сессия на аккаунт.** Любой новый логин (в т.ч. в браузере)
   убивает предыдущую сессию. Нельзя параллелить работу несколькими логинами.
   Пул «sibling»-сессий должен **клонировать** один `ci_session`, а не логиниться
   заново.
2. **`ci_session` ротируется на каждом ответе** (Set-Cookie). httpx подхватывает
   автоматически; но при нескольких клиентах на один аккаунт линии токенов
   форкаются — избегать конкурентных запросов на одном аккаунте.
3. **CSRF (CodeIgniter):** каждый POST должен нести `csrf=<hash>` в теле и иметь
   `csrf_cookie` в jar. Клонам сессий cookie надо копировать.
4. **Скачивание сгенерированных файлов** требует двухсегментного URL
   (`file_id` + пер-файловый токен доступа). Токен есть в разметке страницы
   (`href`/`data-url`), первый сегмент — в `data-file-identifier` и в
   `signature[file_id]` при подписи.
5. **Стадии заявки** (машина состояний): `create → lots → docs → priceoffers →
   preview → public`. `/create/{ann}` со `follow_redirects` редиректит на текущую
   стадию — по конечному URL можно определить, где черновик, и не начинать с нуля.
6. **Цена = «гамма»:** шифруется локальным провайдером **TumarCSP** (не NCALayer)
   через `wss://127.0.0.1:6127/tumarcsp/`: `SetAPIKey → GetVersion →
   EncryptOfferPrice`. Провайдер = `CryptoSocket.exe` (ГАММА Технологии).
   Требует и лицензию ПО, и EFC API-ключ (оба с сроком годности).
7. **Обеспечение заявки** (Приложение 19 / doc 3328) — `typeDoc`:
   `3` = гарантийный денежный взнос (блок на электронном кошельке). Публикация
   не пройдёт, если на кошельке нет суммы обеспечения (~1% от плановой).
8. **`docs_next` — гонка last-writer-wins:** параллельные save-POST'ы затирают
   подписи друг друга. Безопасно — серийно, с GET-барьером между сохранениями,
   тех.спец последним.

## 4. Каким должен быть бот в идеале (ТЗ)

### 4.1 Надёжность
- **Идемпотентность и resume:** уметь продолжить заявку с любой стадии
  (создана / лоты / документы / цена / preview), не начиная заново. Стадию
  определять по редиректу `/create/`. (Частично сделано: `AlreadyPrepared`,
  `AlreadyAtPriceStage`.)
- **Self-heal `docs_next`:** при «Приложение N не подписано» — серийная
  доподпись, затем повтор. (Есть.)
- **Один инстанс:** guard при старте (lock-файл / проверка процесса), иначе
  Telegram Conflict + убийство сессии. **Обязательно.**
- **Никакого долбёжа сервера:** у любого опроса — предел попыток, бэкофф и
  распознавание всех стадий; не молотить 2/сек.

### 4.2 Скорость (T0 критичен)
- Прогрев до T0: логин, пул сессий, коннект TumarCSP, префетч данных.
- На T0 — только критический путь, без ручных подтверждений
  (`confirm_before_submit=false`).
- Оверлап независимых шагов (документы ↔ discover ↔ TumarCSP), но **не** на одном
  аккаунте одновременно там, где сервер этого не терпит.
- **Сделано (fast-T0):** `/schedule` при `defaults.fast_t0: true` — фаза 1
  `stop_after_docs` с момента открытия; фаза 2 в wall-clock T0 —
  `resume_app_id` → только gamma+submit (~5–8с). `docs_next` 1.0с×8.

### 4.3 Preflight-проверки ДО T0 (и алерты в Telegram)
Перед вооружением ставки автоматически проверять и предупреждать:
- баланс электронного кошелька ≥ суммы обеспечения;
- TumarCSP: порт 6127 живой, лицензия действует, **срок API-ключа не истёк**;
- ci_session/логин валиден;
- срок ЭЦП.
Любой фейл — заранее в Telegram, а не падение на T0.

### 4.4 Гибкость (через `/config`, без правки кода)
- `guarantee_type` (тип обеспечения), `dumping_floor_ratio` (цена-пол),
  `dry_run`, `confirm_before_submit`. (Сделано.)
- **Банковская гарантия** как альтернатива денежному взносу: выбор `typeDoc` +
  загрузка файла БГ (сейчас НЕ реализовано — только денежный взнос).

### 4.5 Эксплуатация
- **Авто-обновление EFC API-ключа:** снимать свежий ключ из лога CryptoSocket
  (`%LOCALAPPDATA%\Temp\tumsocket.log.txt`, строки `SetAPIKey apiKey ...`) и
  подставлять в конфиг — без DevTools.
- **Мониторинг сроков:** заранее (например, за 7 дней) слать напоминание об
  истечении лицензии CryptoSocket и EFC-ключа.
- Понятные сообщения об исходе: подана / отменена / dry-run / причина отказа
  сервера (в правильной кодировке — Telegram, не консоль cp1251).

## 5. Правила работы с сервером (rules of engagement)

1. **Ровно один инстанс бота** на аккаунт. Перед стартом — убить старые.
2. **Один логин** — переиспользовать `ci_session` (клонирование для пула), не
   логиниться повторно.
3. **Не параллелить** запросы на одном аккаунте там, где сервер ведёт одну
   сессию/файловую авторизацию; тяжёлые фазы — серийно с барьерами.
4. **Уважать rate limit:** опросы с бэкоффом и лимитом попыток.
5. **Определять стадию** перед действием — не пересоздавать готовый черновик.
6. **Все внешние зависимости — до T0:** кошелёк, TumarCSP (порт+лицензия+ключ),
   ЭЦП. На T0 не должно быть сюрпризов.
7. **Ставку публиковать только после реальной готовности** (документы приняты,
   цена зашифрована, обеспечение обеспечено).

---

## 6. Приоритеты доработок

1. **Preflight-проверки + алерты** (кошелёк, лицензия/ключ TumarCSP, порт 6127) —
   максимум пользы, убирает провалы на T0.
2. **Guard одного инстанса** при старте.
3. **Авто-обновление API-ключа** из лога CryptoSocket.
4. **Мониторинг сроков** лицензии и ключа.
5. **Поддержка банковской гарантии** (выбор typeDoc + upload файла).
6. Полный resume с любой стадии (докрутить сверх `AlreadyAtPriceStage`).
